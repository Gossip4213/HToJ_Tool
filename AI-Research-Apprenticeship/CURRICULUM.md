# 课程大纲 V1.0

## 路线与前置诊断

先建立训练原理与调试能力，再进行适配、智能体交付、偏好优化和长期记忆研究。数学与 Python 按任务补齐：向量与矩阵、导数与链式法则、概率与对数似然、交叉熵、采样误差，以及模块、异常、文件、虚拟环境和 Git。

首课确认现有水平、每周时间和硬件。可跳过已经通过独立诊断的内容；未通过的基础安排到相关项目中补齐。原定六项顺序保留，P02 的 SFT 为 P04 的偏好优化提供基础，P03 提供系统实验平台。

| 阶段 | 核心知识 | 核心交付 | 关键验收 |
| --- | --- | --- | --- |
| P01 MiniGPT | autograd、训练循环、tokenization、因果注意力、位置编码、优化、泛化 | 自己实现的小型 decoder-only Transformer、训练/生成入口、实验报告 | 因果遮罩与张量维度正确；小数据可过拟合；独立验证集有结果；能解释并修改关键代码 |
| P02 Persona-LoRA | 预训练与后训练、SFT、LoRA/QLoRA、数据构造、训练与推理差异 | 开源基座适配器、数据卡、训练配置、对比评估 | 基座、提示词基线与适配器公平比较；保留测试集；检查风格变化、事实性及能力退化 |
| P03 Agent Workbench | 模型接口、工具调用、任务状态、检索、错误恢复、服务与观测 | 有界工具智能体、CLI 或 API、运行记录、评测集 | 正常及失败任务可追踪；权限边界、超时、重试、成本统计可检查；真实任务复现 |
| P04 Alignment Lab | 偏好数据、奖励模型、RLHF 链路、PPO 原理、DPO、奖励投机 | SFT/DPO 对比、最小奖励模型与 RL 演示、消融报告 | 能解释 DPO 与 RLHF 的关系；偏好提升与通用能力分别测量；报告噪声、过拟合与评估偏差 |
| P05 Long-Term Memory | 记忆写入、检索、时间与冲突、更新与遗忘、持续学习 | 带来源和时间的记忆系统、跨会话测试、消融实验 | 新旧信息更新、删除后不再检索、未知信息拒答可测；区分检索错误和生成错误 |
| P06 Personal AI | 系统集成、反馈闭环、巩固、模型迁移、长期运行与研究设计 | 可持续使用的个人助手、成长记录、评估报告 | 更换基座后有迁移测试；保留版本与回滚；个性化、可靠性、成本和退化都有证据 |

以上为最低范围，各项目立项时根据硬件与前序结果冻结规模和指标。P04 的小型 RL 演示用于理解算法，不能据此声称完成了工业规模 RLHF。

## 每项的工作节奏

1. 定义问题、基线、数据边界和完成标准。
2. 原理讲解与小练习；手写关键模块，解释每一步。
3. 最小可运行版本，尽早检查训练或执行是否正确。
4. 控制变量实验、失败分析和必要测试。
5. 文档、复现、答辩、评分与返工。
6. 固定交付版本，更新进度和能力证据。

35–50 天是规划范围，不以熬满天数作为通过条件，也不因日期到了自动通过。必要的训练可使用合适的本地或云资源，但预算须先明确，不能默认学生购买硬件。

## 春招前的安排

从 2026-10-12 起，前三项按串行 35–50 天约为 105–150 天，落在 2027-01-25 至 2027-03-11 左右。作为可调整的初始工作目标，每项约 40 天，前三项约于 2027-02-09 完成；实际春招准备节点须结合目标企业确认。

每项中途即形成可运行版本和展示材料，求职准备可与学习并行。若前序延期，先保证 P01/P02 的可靠交付并缩小 P03 的首版范围；学习顺序、评分和实验严谨性不因赶进度而降低。

## 达标后的能力解释

前三项通过：具备小型训练项目、开源模型适配和智能体应用交付的实证，可用于申请相关初级岗位；仍需按具体职位补齐算法、系统及面试要求。

六项通过：可形成从训练到长期个性化系统的完整工作链路，具备设计对照与消融、复现论文和定位失败的基础。高级研究能力需要进一步独立提出问题、验证贡献并接受外部评审，不能仅由项目数量认定。

行业参照在每次立项时查阅实际岗位、官方文档与同行项目，记录来源、日期及适用范围，避免把课程评分说成统一行业认证。
