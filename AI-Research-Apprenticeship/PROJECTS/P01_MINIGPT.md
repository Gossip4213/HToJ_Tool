# P01 · MiniGPT 项目立项 V1.0

状态：已立项，规模待 L01 冻结 · 计划起点：2026-10-12

## 研究与工程问题

实现一个小型自回归语言模型，验证训练机制正确，观察容量、注意力和训练设置对验证损失及生成的影响。主要目标是理解和复现，不以小模型生成能力替代商业模型。

## 必做范围

- 有合法来源、可获取的文本数据，记录来源、许可和划分方式。
- 先实现简单 tokenization 与 bigram 基线，再实现小型 decoder-only Transformer。
- PyTorch 核心模块可用；attention、causal mask、模型拼接与训练流程需至少独立实现一次。
- 独立的训练、验证、生成入口；配置文件、种子、checkpoint 和恢复训练。
- 覆盖关键正确性的测试：因果遮罩、shape、loss 有限、保存/加载一致。
- 实际训练记录、验证结果、样本与失败分析；至少两项单因素对照，如容量与 context length。
- README、依赖、数据获取、复现命令和实验报告。

数据划分应避免重叠上下文跨越训练/验证边界。规模、步数和预算先用小试验确认，再冻结正式对照设置。

## 里程碑

| 顺序 | 目标 | 证据 |
| --- | --- | --- |
| M0 | 环境与基础诊断 | L01 结果、硬件、时间预算 |
| M1 | bigram 与训练循环 | baseline loss、训练/验证流程和解释 |
| M2 | Transformer 最小实现 | 遮罩/shape 测试、小样本过拟合 |
| M3 | 完整训练与恢复 | 固定配置、checkpoint、验证结果 |
| M4 | 对照与失败分析 | 实验表、真实曲线、局限 |
| M5 | 复现、答辩与交付 | 固定 commit、报告、评分与独立变式 |

建议以约 40 天作为初始计划，通常允许 35–50 天；M0 后据能力调整具体日期。每个里程碑先完成正确性，再扩大规模。

## 交付结构建议

src/：模型、数据与训练模块。
configs/：可复现实验配置。
tests/：必要正确性测试。
reports/：实验表、曲线、报告与失败分析。
README.md：项目问题、安装、运行、结果与限制。
依赖文件：记录实际验证过的版本。

训练数据和大权重使用可复现下载说明或合适的发布方式，不默认提交到 Git 历史。

## 项目硬门槛与答辩

能从干净环境执行小规模复现；训练/验证无泄漏；至少一个真实训练结果；通过关键正确性测试；解释 attention 的输入输出、mask 和梯度更新；独立完成一个实现变式。

最终使用 ASSESSMENT.md 评分。未完成任何训练前，不能填入模型结果或成绩。
